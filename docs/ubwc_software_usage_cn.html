UBWC ENC/DEC 软件使用说明

整理时间：2026-05-11。说明软件首次配置、后续帧配置、中断处理、时钟域约束和 DEC OTF timing 参数填写方式。

基础约定 时钟域 Bank SRAM 配置频率 ENC 使用流程 DEC 使用流程 DEC OTF timing 状态与中断 回归基线

1. 基础约定

APB 寄存器为 32 bit 宽，地址按 4 byte 对齐。所有 64 bit base address 都按低 32 bit、高 32 bit 的顺序写入。

格式编码tile_wtile_h说明
RGBA88880164单平面 RGBA，4 byte/pixel
RGBA10101021164单平面 RGBA，4 byte/pixel
YUV420_8 / NV122328Y + UV 双平面
YUV420_10 / P0103324Y + UV 双平面，16 bit component 存储
当前 RTL 不支持 YUV422_8 和 YUV422_10；软件配置中不要使用这两个 format code。
连续帧模式下，如果格式、分辨率、tile layout 和 OTF timing 不变，软件通常只需要每帧更新 UBWC buffer base address。

2. 时钟域约束

当前 wrapper 级回归使用 OTF 320 MHz、core/VIVO 200 MHz、AXI 500 MHz。APB 只负责寄存器访问，视频数据通路不依赖 APB 时钟。

时钟域频率周期ENC 端口DEC 端口主要逻辑
APB clock100 MHz10.000 nsPCLKPCLKAPB 寄存器访问
AXI/control clock500 MHz2.000 nsi_clki_axi_clkAXI 读写、APB 同步后的控制、状态统计
core/VIVO clock200 MHz5.000 nsi_vivo_clki_vivo_clkVIVO encode/decode core
OTF clock320 MHz3.125 nsi_otf_clki_otf_clkOTF 输入或输出接口
AXI/control、core/VIVO 和 OTF 之间必须通过异步 FIFO 或明确 CDC 逻辑隔离。不要把多 bit payload/counter 直接打两拍跨时钟域。

3. Bank0/Bank1 SRAM 容量要求

ENC 和 DEC wrapper 都把 bank0/bank1 SRAM 留在模块外部实现。两个 bank 的接口都是 128 bit 数据宽度，即每个地址 word 为 16 byte。bank0 和 bank1 是同规格的工作 buffer，软件不需要配置它们的大小，但集成顶层时需要按下面容量提供 SRAM。

模块bank当前 RTL 参数/端口按当前默认参数需要的 RAM说明
ENCbank0COM_BUF_AW=12, COM_BUF_DW=1284096 x 128 bit = 64 KiB = 512 Kbit与 bank1 对称，是 line-to-tile 的 ping-pong 工作区，不固定对应 Y/UV。
ENCbank1COM_BUF_AW=12, COM_BUF_DW=1284096 x 128 bit = 64 KiB = 512 Kbit与 bank0 对称。当前默认 ENC 两个 bank 合计 128 KiB。
DECbank0COM_BUF_AW=12, COM_BUF_DW=1284096 x 128 bit = 64 KiB = 512 Kbit与 bank1 对称，是 tile-to-OTF 的 ping-pong 工作区，不固定对应 Y/UV。
DECbank1COM_BUF_AW=12, COM_BUF_DW=1284096 x 128 bit = 64 KiB = 512 Kbit与 bank0 对称。当前默认 DEC 两个 bank 合计 128 KiB。
当前默认 COM_BUF_AW=12 覆盖 4096 宽 RGBA 与 YUV420 场景。ENC YUV420 采用偶数 Y tile-row 与对应 UV tile-row 共用同一 bank 的时分调度，单端口 SRAM 在冲突周期按读 1 拍、写 1 拍交替，因此每个 bank 固定 4096 x 128 bit 即可。这里的 SRAM 是 wrapper 外部的临时工作 RAM，不是压缩后 UBWC frame buffer。

3.1 ENC bank 容量计算

ENC 的 bank0/bank1 用在 ubwc_enc_line_to_tile，作用是把 OTF 输入行数据重排成 tile 输出。两个 bank 轮流写入/读出，所以每个 bank 都要能容纳一个完整工作组。

// 128 bit word, 1 word = 16 byte
y_tile_cols  = ceil_div(aligned_width_px, tile_w)
uv_tile_cols = 0 for RGBA; otherwise y_tile_cols

// 每个 ENC bank 的最小 word 数
RGBA8888 / RGBA10:
    enc_bank_words = y_tile_cols * 16

YUV420_8 / NV12:
YUV420_10 / P010:
    enc_bank_words = (y_tile_cols + uv_tile_cols) * 16
    // 偶数 Y tile-row 和对应 UV tile-row 放在同一个 bank
    // 通常 uv_tile_cols == y_tile_cols，所以等价于 y_tile_cols * 32

// 参数化实现时
enc_bank_addr_width = ceil_log2(enc_bank_words)
enc_bank_bytes      = 2^enc_bank_addr_width * 16
最大宽度场景格式y_tile_cols最小有效 word 数建议地址宽度每个 bank 容量
4096 pxRGBA8888/RGBA10256409612 bit64 KiB
4096 pxYUV420_8/NV12128409612 bit64 KiB
4096 pxYUV420_10/P010128409612 bit64 KiB

因此当前 ENC 最大 4096 宽配置统一使用 COM_BUF_AW=12，每个 bank 64 KiB，不再为 YUV420 增加到 13 bit。

3.2 DEC bank 容量计算

DEC 的 bank0/bank1 用在 ubwc_dec_tile_to_otf，作用是把 VIVO 解出的 tile 数据重组成 OTF 输出行。外部 bank 容量由顶层参数 COM_BUF_AW 决定。

// DEC 地址空间，128 bit word
dec_bank_words = 2 ^ COM_BUF_AW
dec_bank_bytes = dec_bank_words * 16

// COM_BUF_AW=12 时，4096 像素宽度下的有效地址使用范围
RGBA8888 / RGBA10:
    word 0 .. 4095

YUV420_8 / NV12:
YUV420_10 / P010:
    Y upper region : word 0    .. 1023
    Y lower region : word 1024 .. 2047
    UV region      : word 2048 .. 4095

DEC 的 bank0 和 bank1 是双 buffer 关系：一个 bank 可以保存当前已解好的工作组，另一个 bank 可以继续接收下一组数据。它们不是固定的 Y bank / UV bank，软件也不需要关心 bank 选择。

4. 首次配置和后续配置

场景软件动作
首次配置读取 VERSION/DATE；使能中断；配置格式、尺寸、tile layout、CI/VIVO、metadata geometry、DEC OTF timing；写入第一帧 ENC/DEC 地址。
后续帧配置如果格式、尺寸、layout、timing 不变，只写新一帧的 base address；ENC/DEC 都需要在本帧地址组写完整后写 IRQ_CTRL[5]=1 作为 START token。
重新配置静态项只有格式、分辨率、layout 或 DEC OTF timing 变化时才重写静态项；应先确认当前帧处理完成，再切换静态配置。

4.3.1 ENC 地址和 pitch 计算方法

// 基础函数
ceil_div(a, b) = (a + b - 1) / b
align_up(a, n) = ceil_div(a, n) * n

// 格式参数
RGBA8888:           format=0, tile_w=16, tile_h=4, bpp=4
YUV420_8 / NV12:    format=2, tile_w=32, tile_h=8, bpp=1
YUV420_10 / P010:   format=3, tile_w=32, tile_h=4, bpp=2

// ENC pitch / tile 数
aligned_width_px    = align_up(width_px, tile_w * 4)
y_tile_cols         = ceil_div(aligned_width_px, tile_w)
uv_tile_cols        = 0 for RGBA; otherwise y_tile_cols
stored_y_height     = align_up(height_px, tile_h * 4)
stored_uv_height    = align_up(ceil_div(height_px, 2), tile_h * 4)  // only YUV420
surface_pitch_bytes = align_up(width_px * bpp, tile_w * 4 * bpp)
tile_pitch          = surface_pitch_bytes / 16
meta_pitch          = align_up(y_tile_cols, 64)

// ENC metadata / tile size
y_tile_rows      = ceil_div(stored_y_height, tile_h)
uv_tile_rows     = ceil_div(stored_uv_height, tile_h)                // only YUV420
meta_y_size      = align_up(meta_pitch * align_up(y_tile_rows, 16), 4096)
tile_y_size      = align_up(surface_pitch_bytes * stored_y_height, 4096)
meta_uv_size     = 0 for RGBA; otherwise align_up(meta_pitch * align_up(uv_tile_rows, 16), 4096)
tile_uv_size     = 0 for RGBA; otherwise align_up(surface_pitch_bytes * stored_uv_height, 4096)

// 连续输出 buffer 地址，base 是 Y/RGBA metadata 起始地址
REG_META_BASE_Y  = base
REG_TILE_BASE_Y  = REG_META_BASE_Y + meta_y_size
REG_META_BASE_UV = 0 for RGBA; otherwise REG_TILE_BASE_Y + tile_y_size
REG_TILE_BASE_UV = 0 for RGBA; otherwise REG_META_BASE_UV + meta_uv_size
total_size       = meta_y_size + tile_y_size + meta_uv_size + tile_uv_size

4.4.1 DEC 地址、pitch 和 OTF timing 计算方法

// 基础函数
ceil_div(a, b) = (a + b - 1) / b
align_up(a, n) = ceil_div(a, n) * n

// 格式参数
RGBA8888:           format=0, tile_w=16, tile_h=4, bpp=4
YUV420_8 / NV12:    format=2, tile_w=32, tile_h=8, bpp=1
YUV420_10 / P010:   format=3, tile_w=32, tile_h=4, bpp=2

// DEC pitch / metadata tile 数
aligned_width_px    = align_up(width_px, tile_w * 4)
meta_tile_x_numbers = ceil_div(aligned_width_px, tile_w)             // RGBA/Y plane
stored_y_height     = align_up(height_px, tile_h * 4)
stored_uv_height    = align_up(ceil_div(height_px, 2), tile_h * 4)   // only YUV420
meta_tile_y_numbers = ceil_div(stored_y_height, tile_h)              // RGBA/Y plane
surface_pitch_bytes = align_up(width_px * bpp, tile_w * 4 * bpp)
tile_pitch          = surface_pitch_bytes / 16
meta_pitch          = align_up(meta_tile_x_numbers, 64)

// DEC metadata / tile size
meta_y_size      = align_up(meta_pitch * align_up(meta_tile_y_numbers, 16), 4096)
tile_y_size      = align_up(surface_pitch_bytes * stored_y_height, 4096)
meta_uv_rows     = ceil_div(stored_uv_height, tile_h)                // only YUV420
meta_uv_size     = 0 for RGBA; otherwise align_up(meta_pitch * align_up(meta_uv_rows, 16), 4096)
tile_uv_size     = 0 for RGBA; otherwise align_up(surface_pitch_bytes * stored_uv_height, 4096)

// 连续输入 UBWC buffer 地址，base 是 RGBA/Y metadata 起始地址
REG_META_BASE_Y  = base
REG_TILE_BASE_Y  = REG_META_BASE_Y + meta_y_size
REG_META_BASE_UV = 0 for RGBA; otherwise REG_TILE_BASE_Y + tile_y_size
REG_TILE_BASE_UV = 0 for RGBA; otherwise REG_META_BASE_UV + meta_uv_size
total_size       = meta_y_size + tile_y_size + meta_uv_size + tile_uv_size

// DEC OTF timing 示例
h_total = HSA + HBP + HACT + HFP
v_total = VSA + VBP + VACT + VFP
OTF_CFG0 = {format[4:0], width_px}
OTF_CFG1 = {HSA, h_total}
OTF_CFG2 = {HACT, HBP}
OTF_CFG3 = {VSA, v_total}
OTF_CFG4 = {VACT, VBP}

5. ENC 使用流程

ENC 通过 IRQ_CTRL[5] 写 1 产生 START token。软件先配置好静态参数和输出 buffer 地址，写 IRQ_CTRL[5]=1 后，再送上游 OTF 输入流。

5.1 首次或格式变化时配置

read(0x000); // VERSION
read(0x004); // DATE
write(0x00C, REG_TILE_CFG1);      // [0] four_line_format; [1] lossy_rgba_2_1; [26:16] tile_pitch
write(0x008, REG_TILE_CFG0);      // [0] ubwc_en; [3:1] bank_swizzle; [12:8] highest_bank_bit; [16] bank_spread
write(0x014, REG_ENC_CI_CFG1);    // [16] enc_ci_lossy
write(0x018, REG_ENC_CI_CFG2);    // [30:0] enc_ci_ubwc_cfg_0..9，建议写 0
write(0x01C, REG_ENC_CI_CFG3);    // [5:0] cfg_10; [13:8] cfg_11，建议写 0
write(0x010, REG_ENC_CI_CFG0);    // [0] input_type=1; [10:8] alen=7
write(0x024, REG_OTF_CFG1);       // [15:0] width; [31:16] height
write(0x028, REG_OTF_CFG2);       // [15:0] tile_w; [19:16] tile_h
write(0x02C, REG_OTF_CFG3);       // [15:0] y_tile_cols; [31:16] uv_tile_cols，RGBA 的 uv 写 0
write(0x050, REG_META_ACTIVE_SIZE); // [15:0] active_width; [31:16] active_height
write(0x054, REG_META_PITCH);     // [31:0] meta_data_plane_pitch
write(0x020, REG_OTF_CFG0);       // [2:0] format

5.2 每帧地址配置

地址项APB 地址说明
Y metadata base0x030 / 0x034低 32 bit / 高 32 bit；RGBA 使用该槽位
Y tile base0x038 / 0x03C低 32 bit / 高 32 bit；RGBA 使用该槽位
UV metadata base0x040 / 0x044低 32 bit / 高 32 bit；RGBA 写 0
UV tile base0x048 / 0x04C低 32 bit / 高 32 bit；写完四个地址后写 IRQ_CTRL[5] 启动本帧

写入顺序建议：按 meta Y、tile Y、meta UV、tile UV 顺序写。四个地址建议按顺序写完，然后写 REG_IRQ_CTRL[5]=1 启动本帧。

5.3 后续帧配置

如果格式和尺寸不变，后续帧只需要重复 5.2 的每帧地址配置，写 REG_IRQ_CTRL[5]=1，然后送入下一帧 OTF 输入流。

6. DEC 使用流程

DEC 需要软件显式写 START。首次配置静态参数和一组输入 UBWC buffer 地址后，写 IRQ_CTRL[5]=1 启动；后续帧继续写入新的输入 buffer 地址并再次写 START。

6.1 首次或格式/timing 变化时配置

read(0x000); // VERSION
read(0x004); // DATE
write(0x008, APB_ADDR_TILE_CFG0); // [2:0] bank_swizzle; [8:4] highest_bank_bit; [9] bank_spread; [10] 4line; [11] lossy_rgba_2_1
write(0x00C, APB_ADDR_TILE_CFG1); // [11:0] tile_cfg_pitch
write(0x010, APB_ADDR_TILE_CFG2); // [0] ci_input_type; [8] ci_lossy; [10:9] alpha_mode
write(0x014, VIVO_CFG);           // [0] vivo_ubwc_en; [1] vivo_sreset
write(0x02C, META_CFG0);          // [15:0] Y/RGBA tile_x_numbers; [31:16] Y/RGBA tile_y_numbers
write(0x018, OTF_CFG0);           // [15:0] img_width; [20:16] format
write(0x01C, OTF_CFG1);           // [15:0] h_total; [31:16] h_sync/HSA
write(0x020, OTF_CFG2);           // [15:0] h_bp/HBP; [31:16] h_act/HACT
write(0x024, OTF_CFG3);           // [15:0] v_total; [31:16] v_sync/VSA
write(0x028, OTF_CFG4);           // [15:0] v_bp/VBP; [31:16] v_act/VACT

6.2 每帧地址配置

地址项APB 地址说明
metadata RGBA/Y base0x030 / 0x034低 32 bit / 高 32 bit
tile RGBA/Y base0x038 / 0x03C低 32 bit / 高 32 bit
metadata UV base0x040 / 0x044低 32 bit / 高 32 bit
tile UV base0x048 / 0x04C低 32 bit / 高 32 bit；RGBA 图像不关心
START0x060[5]四类地址都写完后写 1；地址写入只填充队列，不单独启动帧

写入顺序建议：每个 64 bit 地址都按 low word、high word 顺序写。四类地址都写完后，该帧输入 buffer 地址配置完成；随后写 IRQ_CTRL[5]=1 启动本帧。后续帧如果格式和 timing 不变，只重复本节地址配置和 START。

7. DEC OTF timing 配置

软件可以按 video mode timing 图中的 HSA/HBP/HACT/HFP 和 VSA/VBP/VACT/VFP 计算当前 RTL 的 OTF_CFG。RTL APB 写像素/行单位，内部水平计数会转换为 128-bit OTF beat。

图中标记名称软件配置含义
HSAHorizontal Sync Active每一行开头的水平同步脉冲宽度，对应 cfg_otf_h_sync。
HBPHorizontal Back PorchHS 结束后到 active pixel 开始前的水平空白区，对应 cfg_otf_h_bp。
HACTHorizontal Active一行内有效显示/有效数据宽度，对应 cfg_otf_h_act，通常等于输出图像宽度。
HFPHorizontal Front Porchactive pixel 结束后到下一行 HS 前的水平空白区，不单独配置，由 h_total 减去 HSA/HBP/HACT 得到。
VSAVertical Sync Active一帧开头的垂直同步行数，对应 cfg_otf_v_sync。
VBPVertical Back PorchVS 结束后到 active line 开始前的垂直空白区，对应 cfg_otf_v_bp。
VACTVertical Active一帧内有效显示/有效数据行数，对应 cfg_otf_v_act，通常等于输出图像高度。
VFPVertical Front Porchactive line 结束后到下一帧 VS 前的垂直空白区，不单独配置，由 v_total 减去 VSA/VBP/VACT 得到。
RTL 配置项video timing 对应项说明

cfg_otf_h_bpHBP水平 back porch
cfg_otf_h_actHACT水平 active 宽度
cfg_otf_h_totalHSA + HBP + HACT + HFP水平总长度
cfg_otf_v_syncVSA垂直 sync 宽度
cfg_otf_v_bpVBP垂直 back porch
cfg_otf_v_actVACT垂直 active 高度
cfg_otf_v_totalVSA + VBP + VACT + VFP垂直总行数
write(0x01C, {HSA, HSA + HBP + HACT + HFP});
write(0x020, {HACT, HBP});

当前 ubwc_dec_otf_driver.v 中 hsync 只在 active vertical 区间内输出。如果要严格模拟标准 display timing，需要让 hsync 在每一行都按 HSA 输出。
