1. 产品概述

Rotation 图像旋转模块用于对 OTF 输入的 YUV420 图像进行旋转处理，并通过外部 FBC buffer 完成中间帧缓存和输出重排。模块支持 8bit/10bit 输入，内部统一扩展为 16bit，支持 bypass、90 度、180 度、270 度输出。

该模块为内部集成使用的 ASIC 图像处理 IP，设计重点是统一封装 OTF 时序、跨时钟、band SRAM 重排、512bit FBC packet 对齐访问、双帧 base address 管理和连续帧输出控制。

2. 主要特性

格式YUV420 OTF stream，8bit/10bit 输入，内部 Y16/U16/V16。
旋转bypass、rot90、rot180、rot270，超 1920x1080 自动 bypass。
FBC512bit packet，外部 32bit read/write bus，16 beat 传输。
连续帧frame0/frame1 双 base，通过 1bit frame_id 选择。
  • Y/UV stride 支持软件配置，单位为 512bit word。
  • APB、OTF input、core、OTF output 多时钟域独立。
  • OTF input 到 core、core 到 OTF output 使用 mg_async_fifo。
  • line-to-band 使用 Y/UV 独立 ping-pong SRAM。

3. 系统架构

区域说明
Input OTF domain接收 OTF 输入，解析 YUV420 beat，并向 core 侧异步 FIFO 写入数据。
Core clock domain完成格式拆分、band SRAM 写入、旋转读出、512bit pack 和 FBC 调度。
FBC / Output side通过外部 FBC buffer 完成帧缓存，再送入输出侧 OTF driver。
APB clock domain软件寄存器配置和状态读取，通过 CDC 同步到 core/OTF 相关时钟域。
 
正常旋转路径:
otf_parser -> u_otf_in_fifo -> otf_yuv420_stream_adapter
  -> rotation_band_engine -> fbc_write_scheduler -> fbc_writer
  -> External FBC Buffer -> fbc_read_path
  -> u_y_out_fifo / u_uv_out_fifo -> otf_driver
  -> rotation_output_mux -> out_otf_* output

Bypass 路径:
otf_parser -> rotation_bypass_path -> rotation_output_mux -> out_otf_* output

4. 工作流程

4.1 软件配置

  1. APB 读取 VERSION 和 DATE。
  2. 配置 IN_SIZE、CTRL、frame0/frame1 base 和 Y/UV stride。
  3. 每次合法配置写入后，rotation_apb_regs toggle cfg_update_toggle_o。
  4. rotation_cfg_cdc 在 core 时钟域检测 toggle，同步配置。
  5. 软件读取 STATUS，确认 size overflow、force bypass 或 stride clamp。
  6. 上游开始送 OTF 输入帧。
建议在 OTF 输入未启动或帧间空闲时完成寄存器配置。当前 APB 配置 CDC 是逐寄存器更新，不提供多寄存器原子提交屏障。

4.2 输入接收

otf_parser 根据 cfg_in_10bit 解析 otf_pixdata_i[39:0]，8bit/10bit 输入均扩展到 16bit。非 bypass 时，{frame_id, vsync, hsync, fcnt, lcnt, y0, y1, u, v} 写入输入异步 FIFO；bypass 时，数据进入 rotation_bypass_path 内部异步 FIFO。

4.3 Band SRAM 和 FBC 写入

  1. rotation_frame_ctrl 产生 core_frame_start。
  2. rotation_band_engine 启动 Y path 和 UV path。
  3. linear_to_band_sram 将线性 sample 写入当前 band SRAM。
  4. rotate_band_reader 按旋转后的输出顺序读取 SRAM。
  5. row_512_packer 收集同一输出行上的连续 sample，形成 512bit packet。
  6. fbc_write_scheduler 根据 line/word_x 计算 FBC 写地址。
  7. fbc_writer 将 512bit packet 拆成 16 个 32bit beat 写出。

4.4 FBC 读出和 OTF 输出

  1. Y/UV write path 完成并且 FBC write path drain 后，rotation_frame_ctrl 产生 rd_start。
  2. fbc_read_path 根据输出高度、stride、frame_id 和 base address 依次发起 read。
  3. fbc_reader 收集 16 个 32bit beat，还原 512bit Y 或 UV packet。
  4. Y/UV packet 通过两个 512bit async FIFO 送入 OTF 输出时钟域。
  5. otf_driver 消耗 Y/UV packet，生成 normal OTF 输出。
  6. rotation_output_mux 在 normal OTF 和 bypass OTF 之间选择最终输出。

4.5 连续帧 frame_id

frame_id = 0 -> 使用 Y_BASE / UV_BASE
frame_id = 1 -> 使用 Y_BASE1 / UV_BASE1

frame_id 在 OTF 输入帧开始时 toggle，并跟随数据经过 input FIFO、band engine、FBC write/read 和 output path，用于连续帧双 buffer 管理。

7. Line-to-Band SRAM 说明

7.1 32x32 Y Tile 一列搬运到 FBC 的过程

以 rot90 为例，输入 tile 中固定一列 C 的 32 个 Y16 sample，在旋转后会成为输出图像中的一段连续 32 个 Y sample。

Y tile = 32 x 32
选中输入列 C:
  Y[0 ][C]
  Y[1 ][C]
  ...
  Y[31][C]

rot90 read order:
  lane 0  <- Y[31][C]
  lane 1  <- Y[30][C]
  ...
  lane 31 <- Y[0 ][C]

row_512_packer 根据 sample_lane 将 32 个 Y16 写入 512bit packet，随后写入 FBC 中对应的 row-linear 地址。

packet[15:0]     = lane 0
packet[31:16]    = lane 1
...
packet[511:496]  = lane 31

32 x Y16 = 512bit

out_line = C
word_x   = output_x / 32
addr     = Y_BASE + out_line * Y_STRIDE + word_x

关键点：tile 在 SRAM 内用于旋转读出组织；进入 FBC 后不是按 tile-major 存储，而是按输出行 row-linear 的 512bit word 存储。

7.2 Tile 大小和 512bit 对齐关系

Y tile  = 32 x 32
32 x Y16 = 512bit

UV tile = 16 x 16
16 x {U16,V16} = 512bit

7.3 SRAM 容量计算

Y one bank    = 1920 x 32 x 16bit = 120 KiB
Y ping-pong   = 2 x 120 KiB = 240 KiB
RTL parameter = DATA_W=16, ADDR_W=16, DEPTH=61440

UV one bank   = 960 x 16 x 32bit = 60 KiB
UV ping-pong  = 2 x 60 KiB = 120 KiB
RTL parameter = DATA_W=32, ADDR_W=14, DEPTH=15360

Total = 360 KiB = 368640 byte = 2949120 bit

1080 高度决定一帧需要处理多少个 band，不决定单个 SRAM bank 的深度。最后一个 band 不满 32/16 行时复用同一组物理 SRAM。

8. FBC 存储布局

frame_id = 0:
  Y  base = cfg_y_base
  UV base = cfg_uv_base

frame_id = 1:
  Y  base = cfg_y_base1
  UV base = cfg_uv_base1

addr = base + line * stride_words + word_x
字段说明
base当前 frame_id 和 plane 对应的 base address。
line输出图像中的行号。
stride_words每行占用的 512bit word 数，由软件配置并经硬件 clamp。
word_x当前行内第几个 512bit word。

12. 接口时序说明

12.1 OTF input

accept = otf_de_i && otf_ready_o

当 otf_ready_o=0 时，上游需要保持或暂停当前 beat。
otf_vsync_i / otf_hsync_i 与被接受的 pixel beat 一起采样进输入 FIFO。

12.2 OTF input -> core CDC

write side: otf_clk_i, wr_en = !force_bypass && y_valid && uv_valid
read side : clk_i,     rd_en = adapter_in_valid && adapter_in_ready
data      : {frame_id, vsync, hsync, fcnt, lcnt, y0, y1, u, v}

12.3 FBC write

cmd handshake:
w_cmd_vld_o && w_cmd_rdy_i

data handshake:
w_data_vld_o && w_data_rdy_i

每个写命令对应一个 512bit packet。
写命令握手后输出 16 个 32bit data beat。

12.4 FBC read

cmd handshake:
r_cmd_vld_o && r_cmd_rdy_i

data return:
r_data_vld_i && r_data_rdy_o

每个读命令期望返回 16 个 32bit beat。
fbc_reader 收满 16 beat 后输出一个 512bit packet。

12.5 Core -> OTF output CDC

Y path : rd_y_pkt_data[511:0]  -> u_y_out_fifo  -> fifo_y_pkt_data[511:0]
UV path: rd_uv_pkt_data[511:0] -> u_uv_out_fifo -> fifo_uv_pkt_data[511:0]

12.6 OTF output

out_accept = out_otf_de_o && out_otf_ready_i

当前 RTL 行为:
- out_otf_vsync_o 在输出第 0 行时为 1
- out_otf_hsync_o 在每行第一个 pixel pair 时为 1
- out_otf_de_o 在发送 pixel beat 时为 1
- out_otf_ready_i=0 时，otf_driver 停止推进 x/y/lane 计数

even output line: {24'b0, Y1[9:0], Y0[9:0], U[9:0], V[9:0]}
odd  output line: {24'b0, Y1[9:0], Y0[9:0], 20'b0}

12.7 Bypass

当 cfg_force_bypass_out=1 时，rotation_output_mux 选择 bypass path 输出。bypass path 使用内部 66bit async FIFO 从 otf_clk_i 跨到 out_otf_clk_i，不访问 FBC，也不经过 otf_driver。

13. 软件配置建议

  1. 保持上游 OTF 输入停止。
  2. 读取 VERSION、DATE。
  3. 写 IN_SIZE。
  4. 写 CTRL。
  5. 写 frame0 base：Y_BASE、UV_BASE。
  6. 写 frame1 base：Y_BASE1、UV_BASE1。
  7. 写 Y_STRIDE、UV_STRIDE。
  8. 读回 stride，确认是否被 clamp。
  9. 读取 STATUS。
  10. 启动上游 OTF 输入。

14. 使用限制和集成注意事项

  • 输入宽高建议为偶数，以匹配 YUV420。
  • 旋转处理最大支持 1920 x 1080。
  • 超过最大尺寸时硬件强制 bypass。
  • FBC base address 需要满足系统 FBC 地址对齐要求。
  • FBC 每个命令对应 16 个 32bit data beat。
  • 软件需要提供 frame0/frame1 两套 Y/UV base address。
  • 多寄存器配置建议在帧间或输入停止时完成。
  • APB 未定义地址访问会返回 apb_pslverr_o=1。
