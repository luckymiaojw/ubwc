ENC

ENC 1. Feature

特性说明
功能将 OTF 输入像素流编码为 UBWC compressed tile 数据和 metadata，并通过 AXI write master 写入外部 memory。
输入接口OTF input，包含 vsync/hsync/de/data/fcnt/lcnt/ready。
输出接口AXI write master，分别写 compressed tile 数据和 metadata。
推荐时钟APB/PCLK 100 MHz；AXI/i_axi_clk 500 MHz；Core/i_vivo_clk 200 MHz；OTF/i_otf_clk 320 MHz。
支持格式RGBA8888、RGBA1010102、YUV420_8/NV12、YUV420_10/P010、RGBA8888 lossy 2:1。
支持像素尺寸当前 SRAM/line-buffer 规格按最大有效宽度 4096 px 设计；1440x3200 属于该宽度范围内。实际配置以 OTF width/height 和 layout 计算结果为准。
SRAM当前外部工作 SRAM 为 bank0/bank1 两个同规格 bank，单 bank 64 KiB，两 bank 合计 128 KiB。SRAM 容量主要由最大支持图像宽度决定；图像高度只影响行组处理次数，不增加单 bank 容量；小于或等于 4096 px 宽的 RGBA/YUV420 场景复用同一规格 SRAM。
连续帧软件每帧写一组 base address 后写 IRQ_CTRL[5]=1 产生 start token；OTF 数据携带 i_otf_fcnt。若使能 IRQ_CTRL[6]，输入 i_otf_vsync 上升沿会触发 ENC soft reset 并在复位释放后重新 arm frame start。
地址 slot两组地址 slot，硬件按 fcnt[0] 选择 slot0/slot1。
中断正确中断在最后有效输出完成后产生；错误中断用于地址未配置、OTF 行/帧错误、FIFO overflow、VIVO/metadata error。

ENC 4. Diagram

SRAM 项目规格
bank 数量2 个外部 SRAM bank，bank0/bank1
单 bank 容量4096 words x 16 bytes = 64 KiB
使用方式ping-pong 工作 buffer；bank 不是固定 Y/UV plane
SRAM 与图像大小关系容量主要随最大支持宽度变化；高度通过多次行组处理复用同一 bank，不要求随图像高度线性增加。

ENC 5. Work Mode

1. 读取 REG_VERSION / REG_DATE。
2. 图像格式、尺寸或 layout 变化时，配置 TILE_CFG、CI_CFG、OTF_CFG、META_ACTIVE_SIZE、META_PITCH。
3. 每个输出 buffer 到来时，写 META_Y、TILE_Y、META_UV、TILE_UV 四个 64-bit base address。
4. 写 REG_IRQ_CTRL[5]=1 产生 start token；如果需要 VSYNC 自动复位模式，可在初始化时置 REG_IRQ_CTRL[6]=1。
5. 上游按 i_otf_fcnt 输入 OTF frame；在 REG_IRQ_CTRL[6]=1 时，i_otf_vsync 上升沿会先触发 soft reset，再由 reset sequencer 重新 arm frame start。
6. 硬件按 fcnt[0] 选择地址 slot，并写出 compressed tile 和 metadata。
7. 软件读 STATUS/COUNT 处理状态，写 REG_IRQ_CTRL[1]=1 清中断。

ENC 6. Debug

ENC debug 建议先按中断类型分流，再按错误分类读取状态寄存器。正常完成类中断重点看 frame_done、slot 计数和 AXI 写计数；错误类中断重点看地址配置、OTF 输入、metadata 生成、AXI 写 drain 四类状态。读取并保存状态后，再写 REG_IRQ_CTRL[1]=1 清中断和 sticky 状态。

ENC 错误分类定位流程

错误分类优先读取判断方法常见处理
没有中断或中断不符合预期REG_IRQ_CTRL[0]、[4:2]、REG_STATUS2[2:0]先确认中断使能，再区分 correct/error pending。若 pending 已置但外部 IRQ 无输出，检查中断连线；若 pending 未置，继续看 frame_done 与各 stage 计数。使能 IRQ；确认 start 已写入；确认输入 vsync/de 到达。
地址配置类错误REG_STATUS0[9:12]addr_cfg_invalid 表示当前帧 slot 没地址；addr_cfg_overflow 表示软件地址组提交过快。addr_cfg_valid0/1 可判断当前两个 slot 是否可用。按 META_Y、TILE_Y、META_UV、TILE_UV 顺序写完整地址组；先准备地址再 start；overflow 后重新同步 buffer 队列。
OTF 输入格式/行列错误REG_STATUS0[4:5]、REG_OTF_DE_COUNT0/1、REG_OTF_LINE_COUNT0/1bad line 对应单行像素数不一致，bad frame 对应有效行数不一致。DE count 和 line count 可反推上游实际送入的 active 区域。核对 REG_OTF_CFG1、REG_META_ACTIVE_SIZE、上游 lcnt/vsync/de；确认 NV12/P010 第一行 UV 排列与 RTL 配置一致。
OTF-to-tile 或 SRAM 调度阻塞REG_STATUS0[2:3]、REG_OTF_TILE_COUNT0/1busy 长时间为 1 且 tile count 不动，说明 OTF-to-tile 内部被反压；overflow 置位说明上游仍在送入但内部无法消耗。看波形中的 line-to-tile FIFO ready、bank read/write 仲裁、AXI 写 ready；确认 YUV420 UV_A/UV_B 调度没有浪费 SRAM 带宽。
metadata 生成错误REG_STATUS0[6:7]、REG_META_COUNT0/1、REG_META_AXI_W_CNT0/1meta_err_0 偏向 buffer overflow；meta_err_1 偏向坐标/顺序/地址递增错误。meta count 与 meta AXI W count 的差距可判断是生成端还是写出端异常。检查 metadata pitch、Y/UV plane 切换、slot/fcnt、tile 坐标和 AXI 写 ready。
AXI 写通路错误或性能不足REG_TILE_AXI_W_CNT0/1、REG_META_AXI_W_CNT0/1、REG_STATUS0[13]OTF/tile/meta 计数增长但 AXI W 计数停住，说明写通路被 AXI ready 或 response 阻塞。soft reset 时若 drain timeout 置位，说明 outstanding 长时间无法排空。检查 interconnect/slave ready、B response、AXI ID/len/size 配置；复位前尽量停止上游输入并等待 idle。
正常完成但输出数据不符合预期全部 slot count、frame_done先确认 correct IRQ 和 frame done，再比对每个 slot 的 OTF DE/line、tile、metadata、tile AXI、meta AXI 数量是否匹配预期。数量匹配但内容错，优先看 base address、pitch、format 配置。核对 ubwc_cfg 生成结果、vector ReadMe 中的 stored layout、metadata pitch 和压缩数据地址。

bank 数量2 个外部 SRAM bank，bank0/bank1

SRAM 与图像大小关系容量主要随最大支持宽度变化；高度通过多次行组处理复用同一 bank，不要求随图像高度线性增加。

DEC 5. Work Mode

1. 读取 REG_VERSION / REG_DATE。
2. 图像格式、尺寸、layout 或 OTF timing 变化时，配置 TILE_CFG、VIVO_CFG、META_CFG0、OTF_CFG0..4。
3. 每个输入 UBWC buffer 到来时，写 META_Y、TILE_Y、META_UV、TILE_UV 四个 64-bit base address。
4. 写 APB_ADDR_IRQ_CTRL[5]=1 产生 start token。
5. 硬件读取 metadata 和 tile 数据，驱动 VIVO 解压。
6. tile-to-OTF 按 OTF timing 输出视频。
7. 软件读 STATUS/STAT 处理状态，写 IRQ_CTRL[1]=1 清中断。

DEC 6. Debug

DEC debug 建议按“start 是否被接收、metadata 是否读到、tile 是否读到、VIVO 是否消耗、OTF 是否输出”五级流水定位。错误中断先区分 metadata/tile AXI read、VIVO、tile-to-OTF/ready 三类；正常完成但图像异常时，优先用 OTF line/de 计数和 metadata/tile 计数核对配置。

APB_ADDR_STATUS0[0] frame_activeframe 是否已经启动并仍在途start 后该 bit 应进入 active。若 start 已写但始终为 0，检查 APB_ADDR_IRQ_CTRL[5] 写入、地址组是否完整、reset 是否释放。
APB_ADDR_STATUS0[1] meta_busymetadata read stage 是否忙用于确认 metadata AR/R 请求是否被发起和消耗。若一直 busy，优先看 AXI AR ready/R valid、metadata FIFO almost full 和 metadata base address。
APB_ADDR_STATUS0[2] tile_busytile read stage 是否忙用于定位 tile address generator、tile AXI read、tile-to-line 写入是否还在推进。若 tile busy 长时间为 1 且 tile count 不变，重点看 AXI read ready/response 或 SRAM 写入仲裁。

APB_ADDR_STATUS0[4] otf_busytile-to-OTF 是否仍在输出用于判断 line buffer、CDC FIFO、OTF timing driver 是否仍有数据在途。若 otf busy 为 1 但 de/line count 不增长，优先检查 i_otf_ready 和 OTF FIFO。
APB_ADDR_STATUS0[5] all_stage_idle所有 busy 输入是否为 0用于软件判断是否可以安全重新配置静态寄存器。该 bit 只是实时 idle 汇总，不等同于 frame done。
APB_ADDR_STATUS0[6] frame_idle_doneframe active 已结束且所有 stage idle用于确认最后一帧数据已经从内部流水排空。若 correct IRQ 已产生但该 bit 不为 1，说明还有尾部数据或状态未 drain。
APB_ADDR_STATUS1[4:0] stage_done各 stage 完成 bitmap用于判断 metadata、tile、VIVO、OTF、frame 哪一级已经产生完成事件。若 frame 未完成，可用该字段定位最后完成到哪一级。
APB_ADDR_STATUS1[8:5] stage_seen各 stage 是否曾经进入 busy用于区分“没启动”和“启动后卡住”。例如 meta_seen=0 表示 metadata 阶段从未开始；meta_seen=1 但 meta_done=0 表示 metadata 阶段卡住。
APB_ADDR_STATUS2[0] vivo_idleVIVO 子模块实时 idle用于判断 VIVO 内部是否空闲。它是实时状态，不参与中断分类；调试 VIVO 卡死时与 vivo_busy 交叉确认。
APB_ADDR_STATUS3[6:0] vivo_errorVIVO 子模块错误 bitmap用于定位解压核内部错误。若该字段非 0，即使 AXI 和 OTF 计数正常，也需要优先排查 metadata 内容、tile payload、format/lossy 配置。

APB_ADDR_STAT_TILEtile address generator 数量用于判断 metadata 是否成功驱动 tile read。若 metadata count 增长但 tile count 不增长，问题在 metadata decode 到 tile AR 之间。
APB_ADDR_STAT_OTF_TILEtile-to-OTF accepted tile 数量用于判断解压后的 tile 是否进入 OTF 输出路径。若 tile count 增长但 OTF tile 不增长，问题在 VIVO 输出、line buffer 或 tile-to-OTF 接收。
APB_ADDR_STAT_OTF_LINEOTF 输出行数量用于核对最终输出行数。正常情况下应对应 OTF_CFG4.v_act 的 active 行数；若少行，检查 OTF ready 和 line buffer drain。
APB_ADDR_STAT_OTF_DEOTF 有效输出 beat 数量统计 o_otf_de && i_otf_ready。用于核对最终输出像素/beat 数，也可定位下游 ready 拉低导致的输出停顿。

DEC 错误分类定位流程

错误分类优先读取判断方法常见处理
start 后无任何推进APB_ADDR_IRQ_CTRL[5]、APB_ADDR_STATUS0[0]、APB_ADDR_STATUS1[8:5]如果 frame_active=0 且 stage_seen=0，说明 start token 没有进入数据链路或地址配置不完整。若 frame active 为 1 但 stage_seen 不变，检查 reset、clock 和 start CDC。确认每帧地址组已写完；写 APB_ADDR_IRQ_CTRL[5]=1；确认 AXI/OTF/VIVO 复位释放。
metadata read 类错误APB_ADDR_STATUS0[1]、APB_ADDR_STAT_META、AXI AR/R handshakemetadata busy 长时间为 1 且 stat_meta 不增长，说明 metadata AXI read 或 metadata decode 卡住。若 AR valid 长时间等待 ready，说明 interconnect/slave 侧反压；若 R response 为 SLVERR/DECERR，应归类为地址或 memory error。检查 REG_META_BASE_Y/UV、metadata pitch/layout、AXI read ready/response；确认 metadata 接收 FIFO 未满。
tile read 类错误APB_ADDR_STATUS0[2]、APB_ADDR_STAT_TILE、AXI AR/R handshakemetadata count 增长但 tile count 不增长，说明 metadata 到 tile AR 之间异常；tile count 增长但后级不动，说明 tile data read 或 SRAM 写入被阻塞。检查 REG_TILE_BASE_Y/UV、tile address 计算、AXI R response、SRAM write/read 仲裁。
VIVO 解压类错误APB_ADDR_STATUS0[3]、APB_ADDR_STATUS2[0]、APB_ADDR_STATUS3[6:0]vivo_error 非 0 表示解压核内部错误；vivo_busy=1 且 vivo_idle=0 长时间不退，说明输入 tile 或 metadata 被 VIVO 接收后未完成。核对 format/lossy/4-line 配置，检查 metadata alen/payload、tile 数据内容，以及 VIVO ready/valid。
OTF 输出类错误APB_ADDR_STATUS0[4]、APB_ADDR_STAT_OTF_TILE、APB_ADDR_STAT_OTF_LINE、APB_ADDR_STAT_OTF_DEOTF tile 增长但 line/de 不增长，说明 tile-to-OTF 或 OTF driver 被下游 ready 阻塞；line count 少于 v_act，说明最后几行未 drain；de count 少于 h_act * v_act 对应 beat，说明 active 区输出不足。检查 i_otf_ready、OTF timing 配置、CDC FIFO 深度、line buffer 读出状态。
正常完成但图像尺寸或内容异常APB_ADDR_STATUS4[2]、APB_ADDR_STAT_OTF_LINE、APB_ADDR_STAT_OTF_DE、metadata/tile count先确认 correct IRQ，再核对 OTF 行数和 DE beat 数是否符合 h_act/v_act。若数量正确但内容异常，重点检查 base address、stored layout、metadata tile count、Y/UV 地址顺序。按 ubwc_cfg 重新生成配置；对照 vector ReadMe 检查 metadata、compressed tile 和 line data 地址排列。
性能或 AXI 延迟导致断流APB_ADDR_STATUS0[1:4]、APB_ADDR_STAT_*、波形中的 AR/R ready如果 metadata/tile 阶段周期性停住，通常是 AXI read latency 或 SRAM 调度造成。若 OTF de count 出现间断，说明 tile-to-OTF 没有提前准备足够 line data。增大 CDC/line buffer 深度，提前发 AR，检查 metadata AR outstanding 限流；P010 对 AXI read 带宽更敏感。
清中断后状态未恢复APB_ADDR_IRQ_CTRL[1]、APB_ADDR_STATUS0、APB_ADDR_STATUS1IRQ clear 只清 pending/sticky，不等同于强制清空仍在途数据。若 busy 仍为 1，说明硬件仍在处理或等待下游 ready。清中断前先保存状态；若需要重新开始，应等待 frame_idle_done 或执行系统级 reset 流程。
