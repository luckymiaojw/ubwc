UBWC 配置辅助库使用说明

本文说明 ubwc_cfg 目录中的 C 和 SystemVerilog 配置辅助代码如何使用。 目标是让软件或仿真环境输入图像格式、像素尺寸、首地址和 OTF timing 后，得到 ENC/DEC APB 寄存器写入序列。

覆盖模块 ENC / DEC
主要入口 C API + SV task
生成内容 APB 写寄存器表
版本状态 R0 回归通过

1. 使用范围

ubwc_cfg 是一套轻量配置辅助代码，不直接驱动硬件，也不包含 APB bus functional model。 它负责根据格式和分辨率计算 UBWC layout、pitch、tile 数、地址基址，并输出 APB 写寄存器序列。

软件侧

使用 ubwc_cfg/tools/*.h 在 firmware、bring-up 程序或寄存器 dump 工具中生成写寄存器表。

仿真侧

使用 ubwc_cfg/include/*.sv 和 *.svh 在 testbench 中调用 APB 写 task。

输入基址约定： API 的 meta_y_base_addr 是一帧 UBWC buffer 的起始地址。辅助库会按 META Y -> TILE Y -> META UV -> TILE UV 的顺序自动推导其他三个基址。

4. 快速生成寄存器

最快的检查方式是编译 dump 工具。dump 工具会打印 tile 参数、layout size、layout base，以及完整 APB 写序列。

4.1 ENC 示例

cc -std=c99 -Wall -Wextra -I ubwc_cfg/tools \
  ubwc_cfg/tools/ubwc_enc_cfg_dump.c \
  -o /tmp/ubwc_enc_cfg_dump

/tmp/ubwc_enc_cfg_dump nv12 544 1200 0x10000000

输出中应重点检查这些信息：

  • surface_pitch_bytes 和 tile_pitch 是否符合期望。
  • layout bases 是否按 meta_y/tile_y/meta_uv/tile_uv 排列。
  • 最后一笔是否写 REG_IRQ_CTRL，默认值通常为 0x00000021。

4.2 DEC 示例

cc -std=c99 -Wall -Wextra -I ubwc_cfg/tools \
  ubwc_cfg/tools/ubwc_dec_cfg_dump.c \
  -o /tmp/ubwc_dec_cfg_dump

/tmp/ubwc_dec_cfg_dump rgba8888 4096 600 0x20000000
dump 工具使用默认 DEC OTF timing：h_total=h_act=width， v_total=v_act=stored_height，sync/back porch 为 0。 真实系统通常需要在 C API 或 SV full task 中显式填写 OTF timing。

5. C API 使用

5.1 ENC 一键生成写寄存器表

#include "ubwc_enc_cfg.h"

void program_enc(uint32_t width, uint32_t height, uint64_t frame_base)
{
    ubwc_enc_reg_write_t regs[32];
    size_t n;
    size_t i;

    n = ubwc_enc_make_reg_writes_from_base(
        UBWC_ENC_FMT_YUV420_8_NV12,
        width,
        height,
        frame_base,
        regs,
        32);

    for (i = 0; i < n; ++i) {
        apb_write(regs[i].addr, regs[i].data);
    }
}

5.2 DEC 带 OTF timing 的推荐写法

#include "ubwc_dec_cfg.h"

void program_dec(uint32_t width, uint32_t height, uint64_t frame_base)
{
    ubwc_dec_base_cfg_t base;
    ubwc_dec_config_t cfg;
    ubwc_dec_reg_write_t regs[32];
    size_t n;
    size_t i;

    base = ubwc_dec_layout_bases(UBWC_DEC_FMT_YUV420_8_NV12,
                                 width,
                                 height,
                                 frame_base);
    cfg = ubwc_dec_default_config(UBWC_DEC_FMT_YUV420_8_NV12,
                                  width,
                                  height,
                                  &base);

    cfg.h_sync  = 8;
    cfg.h_bp    = 40;
    cfg.h_act   = width;
    cfg.h_total = cfg.h_sync + cfg.h_bp + cfg.h_act + 40;

    cfg.v_sync  = 4;
    cfg.v_bp    = 12;
    cfg.v_act   = ubwc_dec_stored_height_px(cfg.format, height);
    cfg.v_total = cfg.v_sync + cfg.v_bp + cfg.v_act + 8;

    cfg.irq_enable = 1;
    cfg.do_start   = 1;

    n = ubwc_dec_make_reg_writes_ex(&cfg, regs, 32);
    for (i = 0; i < n; ++i) {
        apb_write(regs[i].addr, regs[i].data);
    }
}

5.3 常用函数

函数 说明
ubwc_*_layout_sizes() 计算 metadata/tile 各 plane size 和 total size。
ubwc_*_layout_bases() 根据 meta_y_base_addr 推导四个 plane 的起始地址。
ubwc_*_default_config() 生成默认配置结构体，适合再手动覆盖 lossy、timing、start 等字段。
ubwc_*_make_reg_writes_ex() 从完整 config 结构体生成 APB 写序列，推荐真实软件使用。
ubwc_*_make_reg_writes_from_base() 最简入口，只输入格式、尺寸和 frame base，适合 smoke test。

6. SV APB task 使用

SV 版本用于 testbench。使用前需要由 testbench 提供一个名为 apb_write 的 task， ubwc_*_apb_program.svh 会直接调用它。

6.1 ENC testbench 示例

import ubwc_enc_cfg_pkg::*;
`include "ubwc_cfg/include/ubwc_enc_apb_program.svh"

task automatic apb_write(input logic [15:0] addr,
                         input logic [31:0] data);
    // testbench APB write implementation
endtask

initial begin
    ubwc_enc_apb_program_simple(
        UBWC_ENC_FMT_YUV420_8_NV12,
        544,
        1200,
        64'h0000_0000_1000_0000);
end

6.2 DEC testbench 示例

import ubwc_dec_cfg_pkg::*;
`include "ubwc_cfg/include/ubwc_dec_apb_program.svh"

task automatic apb_write(input logic [15:0] addr,
                         input logic [31:0] data);
    // testbench APB write implementation
endtask

initial begin
    ubwc_dec_apb_program_simple_full(
        UBWC_DEC_FMT_YUV420_8_NV12,
        544,
        1200,
        64'h0000_0000_2000_0000,
        640, 8, 40, 544,
        1232, 4, 12, 1216,
        1'b0,
        1'b1,
        1'b1);
end
选择 simple 还是 full： simple 适合默认 timing 的 fake 仿真； simple_full 和 *_program_full 适合明确配置 active size、OTF size、timing、lossy、irq 和 start。

7. 配置模式

配置内容 配置频率 说明
格式、tile、CI、bank swizzle、lossy 图像格式或策略变化时配置 格式不变时通常不用每帧重复配置。
ENC OTF 输入尺寸、active size、metadata pitch 图像格式、尺寸或 layout 变化时配置 包括 OTF_CFG*、META_ACTIVE_SIZE、META_PITCH。
DEC OTF timing 输出 timing 变化时配置 包括 H_TOTAL/H_SYNC/H_BP/H_ACT 和 V_TOTAL/V_SYNC/V_BP/V_ACT。
ENC 每帧输出地址 每个输出 UBWC buffer 配置一次 写 0x030..0x04c 四个 64-bit 地址，然后写 start。
DEC 每帧输入地址 每个输入 UBWC buffer 配置一次 写 0x030..0x04c 四个 64-bit 地址，然后写 start。
辅助库默认输出完整寄存器序列，适合首帧配置、格式切换或仿真。稳定运行时，软件可以只更新每帧地址和 start。

8. 地址与 pitch 计算

8.1 地址排列

meta_y_base = frame_base
tile_y_base = meta_y_base + meta_y_size

RGBA:
    meta_uv_base = 0
    tile_uv_base = 0

YUV420:
    meta_uv_base = tile_y_base + tile_y_size
    tile_uv_base = meta_uv_base + meta_uv_size

ENC 和 DEC 使用同一套 layout 思路：Plane Y 表示 RGBA/Y plane，Plane UV 表示 YUV420 的 UV plane。 对 RGBA 格式，UV 相关寄存器可以写 0，辅助函数也会自动生成 0。

8.2 关键计算

参数 计算规则 说明
tile_w RGBA 为 16，YUV420 为 32 以像素为单位。
tile_h RGBA/P010 为 4，NV12 为 8 以像素行为单位。
bpp RGBA 为 4，NV12 为 1，P010 为 2 用于计算 surface pitch。
surface_pitch_bytes align(width * bpp, tile_w * 4 * bpp) 压缩 tile 数据所在 plane 的行 pitch。
tile_pitch surface_pitch_bytes / 16 写入 TILE_CFG 的 pitch 单位。
stored_height align(height, tile_h * 4) 存储高度，不一定等于有效图像高度。
meta_pitch align(tile_cols, 64) metadata plane pitch。
meta_size align(meta_pitch * align(tile_rows, 16), 4096) metadata plane 4KB 对齐。
tile_size align(surface_pitch_bytes * stored_height, 4096) compressed tile plane 4KB 对齐。

11. DEC OTF timing

DEC 输出 OTF timing 采用常见 video mode 标记。配置寄存器只关心数量，不自动推导 blanking。

字段 含义 典型计算
H_SYNC 水平同步宽度 HSA 由显示 timing 给出
H_BP 水平后肩 HBP 由显示 timing 给出
H_ACT 水平有效像素 HACT 通常等于输出有效宽度
H_TOTAL 一行总周期 H_SYNC + H_BP + H_ACT + HFP
V_SYNC 垂直同步行数 VSA 由显示 timing 给出
V_BP 垂直后肩 VBP 由显示 timing 给出
V_ACT 垂直有效行数 VACT 通常使用 stored_height 或系统要求的有效输出高度
V_TOTAL 一帧总行数 V_SYNC + V_BP + V_ACT + VFP
注意： ubwc_dec_apb_program_simple() 只适合 fake/smoke 仿真。真实 OTF 输出建议使用 ubwc_dec_apb_program_simple_full() 或 C 的 ubwc_dec_config_t 显式配置 timing。

12. START 和中断

寄存器 bit 方向 说明
IRQ_CTRL [0] RW irq_enable，中断使能。
IRQ_CTRL [1] W1P irq_clear，清中断脉冲。该位不由 helper 默认写入。
IRQ_CTRL [5] W1P start，启动一帧处理。helper 在 do_start=1 时写 1。
默认 helper 末尾写 IRQ_CTRL = 0x00000021，表示中断使能并发出 start。 如果软件希望先写静态寄存器、后续再单独 start，可以将 do_start 设为 0，之后单独写 bit5。

13. 检查清单

检查项 期望
format code 只使用表格中列出的 format code，避免和业务侧私有枚举混用。
首地址 meta_y_base_addr 是整帧 UBWC buffer 起始地址，建议至少 4KB 对齐。
RGBA 的 UV 地址 RGBA 不关心 UV，helper 会写 0。为了保持寄存器序列一致，建议软件也按 helper 写完整地址组。
YUV420 的 UV height UV plane 使用 ceil(height / 2) 参与 size 计算。
DEC OTF timing 真实系统必须根据 panel/后级模块 timing 显式配置，不建议依赖 simple 默认值。
每帧启动 每个新 buffer 写地址组后，再写 IRQ_CTRL[5]=1 发 start。
输出表容量 C API 建议分配 ubwc_*_reg_write_t regs[32]，当前足够容纳完整写序列。

本文对应当前 ubwc_cfg 目录实现；寄存器 bit field 的最终定义以 docs/ubwc_enc_reg_table.xlsx、docs/ubwc_dec_reg_table.xlsx 和 RTL APB block 为准。
